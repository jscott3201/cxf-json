# W-004 evidence: Source-fidelity contract

Status: implementation complete; PR creation, review, and merge pending.

Evidence date: 2026-08-09.

## Scope

W-004 operationalizes D-014 and D-023. It defines document retention, duplicate
member policy, number-spelling limits, parser positions, optional JSON Pointers,
and RDF-term evidence. It does not add a source mapper, public API, or
source-to-RDF provenance.

The acceptance contract is in
[`W004-SOURCE-FIDELITY-CONTRACT.md`](../W004-SOURCE-FIDELITY-CONTRACT.md).

## Implementation

Ordinary JSON and JSON-LD now use the same project-owned lexical preflight. It
walks JSON with an explicit stack, records decoded object names in a
standard-library `HashSet`, and uses `serde_json` to decode individual strings.
Numbers are checked lexically rather than converted. A repeated name stops
processing before last-wins data reaches a result. The scanner builds no AST,
retains no successful-value positions, and adds no package.

An explicit UTF-8 check runs first, so an earlier large number cannot mask the
first invalid byte. The preflight adds no nesting ceiling; W-011 owns the
production limit before allocation-heavy processing.

`SourceDocument` retains the submitted bytes on success and failure. Parser
ranges derive zero-based line and byte-column values from offsets into that
buffer. Upstream ranges are clamped so `start <= end <= input length`. Point
diagnostics use equal start and end positions.

`ProbeDiagnostic` carries optional `pointer` and `rdf_term` fields. A Serde
round-trip proves the DTO's JSON representation, not a host adapter or a
relationship between those fields. `ProbeFailure` boxes the diagnostic to keep
the error variant below Clippy's large-result threshold without changing the
serialized shape.

## Behavioral evidence

### Duplicate names

Tests reject duplicate decoded names at the root, in a nested object, in an
object inside an array, and in `@context`. `"a"` and `"\u0061"` conflict. The
preflight does not normalize Unicode; `"é"` and `"e\u0301"` remain distinct.
Duplicate failures retain the source and expose neither a JSON Pointer nor an
RDF term because RFC 6901 evaluation is undefined for duplicate names.

### Numbers and source

The retained source preserves `1`, `1.0`, `1e+02`, `-0`, a large integer, and a
long fraction exactly. Serde semantic values normalize or round those forms. The
RDF path canonicalizes the four common forms and accepts `1e400` without routing
it through `f64`. Neither semantic representation is treated as a lexical-number
API.

### Locations

Malformed JSON, invalid UTF-8, EOF, multibyte UTF-8 before an error, LF, and CRLF
cases pin byte positions. Invalid UTF-8 points to the first invalid byte. Other
syntax ranges are parser detection points rather than guaranteed token spans.
Syntax errors entering through the JSON-LD path now fail in the JSON stage before
semantic processing.

### Source and graph evidence

Named subjects, predicates, objects, datatypes, language tags, and graph names
remain available as owned RDF summaries. Anonymous nodes remain processor
identifiers. Compact/full-IRI equivalence and ordinary-array reordering continue
to demonstrate that RDF identity and set relationships cannot supply source
provenance or CXF order.
