# W-003 evidence: CXF ingestion qualification

Status: local evidence complete; pull-request qualification pending.

Evidence date: 2026-08-09.

## Scope

This result evaluates OxJSONLD/OxRDF only as a private CXF ingestion stage. It
does not claim general JSON-LD conformance, define the public CXF model, or adopt
the dependencies for a production release.

The operation matrix and acceptance gates are in
`W003-CXF-INGESTION-QUALIFICATION.md`.

## Owned operation matrix

Five repository-authored CXF fixtures cover compact and full IRIs, top-level
`@graph`, node and value objects, scalar/array property spelling, ordered context
maps, and CXF array reordering.

| Result | Count |
|---|---:|
| Files | 5 |
| Passed | 5 |
| Input bytes | 5,004 |
| RDF quads | 52 |
| Harness elapsed | 3,900 microseconds |

The compact and full-IRI documents produce the same 20 sorted RDF quads. A
single object and a single-element array also produce the same relationship.
Later inline context definitions replace earlier definitions as required by
context processing order.

The two `containsBlock` documents differ only in array order and produce equal
RDF. This is a required negative capability result: ordinary JSON-LD arrays are
sets after RDF conversion. Open Control Engine assigns meaning to several CXF
array orders, so ordered CXF projection must use retained source/DTO order rather
than RDF iteration order. D-020 records that boundary.

The sole failure is
`crates/oce-cxf/tests/fixtures/node_scoped_contexts.jsonld`. That fixture embeds
a remote context reference and receives the expected deterministic
`No LoadDocumentCallback has been set to load remote contexts` failure. The same
policy is pinned by the repository-owned remote-context test. No HTTP, TLS,
network-capable loader, or async-runtime dependency appears in `Cargo.lock`.

Open Control Engine is a narrower semantic consumer and is not the validity
oracle. Its semantic accept/reject results were not compared with RDF parse
success. The 44 vendored producer files are external compatibility evidence,
not repository fixtures; W-005 still owns redistribution and automated-fetch
policy.

The first corpus count includes eight tracked `.export.cxf.json` wire goldens in
addition to its `.jsonld` files. Corpus roots and expected failures are
canonicalized before reporting, so alias paths cannot inflate totals.
`--expect-failure` also pins the exact diagnostic message. A new or changed
parse failure, an expected failure that starts passing, or a read failure returns
a nonzero exit.
